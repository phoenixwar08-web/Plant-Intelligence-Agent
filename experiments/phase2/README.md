# WYC 完整动态分段双模型训练程序 v1.9.0

本程序独立训练自然湿度变化模型和浇水响应模型，不依赖 Phase 3、不控制水泵。

## 预测依据

每次预测使用最近连续 12 条传感器数据，输入特征包括：

- 温度、湿度、光照、电导率。
- 是否浇水、浇水秒数。
- 温度变化、湿度变化、距离上次浇水时间。

模型使用轻量 Transformer、位置编码、SmoothL1Loss、Adam、梯度裁剪、
轨迹平滑损失、自然异常上升惩罚及峰值一致性损失。

本版本没有把“单次响应段累计浇水秒数”新增为独立模型特征；模型仍使用
原有逐行 `water_seconds` 输入。其余八项可靠性与评估改进均已实现。

## 阶段与分段训练

程序每轮从历史窗口确定性重建四个阶段：

```text
NATURAL
WATERING
RESPONSE_RISING
RESPONSE_SETTLING
```

每个自然段和浇水响应段拥有唯一 `segment_id`。预测任务只能学习相同
`segment_id` 内的真实值。发生阶段变化后，即使之后重新进入相同状态，
旧任务也不会恢复训练。

每获得一个新的整小时真实值，程序使用小时掩码只训练该小时一次：

```text
0  尚未获得真实值
1  已执行反向传播
-1 阶段已经变化，不属于该任务
```

## 连续浇水合并

连续浇水行会按完整响应段合并为一次浇水事件：

- 浇水秒数累计。
- 同一次事件只进入训练集或验证集一次。
- 浇水模型学习整个上升和扩散阶段，而不是只学习 `是否浇水=1` 的行。

间隔不超过 30 分钟且属于同一响应段的浇水行为合并为一个事件，防止一次
浇水被重复放入训练集和验证集。

## v1.9.0 八项改进

1. `segment_id` 由阶段起始时间生成；同一份历史数据重复扫描时编号稳定。
2. 独立预测到达峰值时间和回归自然期时间；时间预测头单独训练，不破坏轨迹模型。
3. 明确合并连续浇水事件，并按完整响应段生成一个训练样本。
4. 隔离重复时间、倒序、过大时间缺口、湿度突跳及传感器越界数据。
5. 按浇水秒数分别统计验证样本量、MAE 和低/中/高置信度。
6. 在线预测记录基于样本量和验证误差计算的预测置信度。
7. 五分钟周期只处理新增标签；完整历史训练、基线学习和验证每天执行一次。
8. 记录当前 RSS、周期耗时、队列和反向传播次数；内存接近阈值时暂停在线训练。

## 动态自然基线

平稳期标准不是固定值。程序根据历史无浇水数据按以下环境分组统计：

- 白天或夜间。
- 温度区间。
- 湿度区间。

每组自动计算自然变化速度、30 分钟波动范围和变化斜率的 95% 分位数。
对应分组样本不足时才回退到全局自然基线。只有连续多个窗口重新符合
自然基线后，才从浇水响应模型切换自然模型。

## 验证和模型保护

- 训练集使用较早数据。
- 验证集使用时间尾段。
- 两者之间保留至少 12 小时隔离区，避免重叠窗口造成数据泄漏。
- 连续浇水事件不会跨训练集与验证集拆分。
- 每天验证一次。
- 验证通过后才晋升正式权重。
- 验证失败时自动恢复上一版已验收权重。

## 内存和负载限制

- CSV 最多读取最近 100,000 行。
- 内存中最多构造 15,000 个自然样本。
- PyTorch CPU 线程数为 1。
- 在线批量最多 16。
- 每个周期最多执行 8 个小时标签的反向传播。
- 等待任务最多 96 条并最多保留 72 小时。
- 过期任务写入 `expired_tasks.csv`。
- systemd 内存硬上限为 512 MB。

## 主要输出

- `natural_predictions.csv`：自然模型预测。
- `online_predictions.csv`：浇水响应模型预测。
- `natural_backprop_log.csv`：自然模型分段反向传播记录。
- `online_backprop_log.csv`：浇水模型分段反向传播记录。
- `response_events.csv`：实际峰值、到峰时间和进入自然期时间。
- `segmented_training_queue.json`：任务、`segment_id` 和小时训练掩码。
- `model_readiness.json`：每日严格验证结果。
- `data_quality_issues.csv`：被隔离的异常数据及原因。
- `resource_usage.csv`：周期耗时、当前内存、任务数和训练暂停状态。
