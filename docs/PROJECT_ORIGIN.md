# 项目来源与新主线定位

## 为什么建立新仓库

`Plant-Intelligence-Agent` 是未来植物智能体系统的正式 GitHub 主线。它解决的不是“把一个旧仓库整理得更漂亮”，而是把已经运行的多设备物理智能体系统逐步变为可维护、可审计、可复现的工程与研究平台。

旧 `auto_water` 仓库不能承担此角色：它只覆盖历史 soil3 工程的一部分，且不等同于当前生产运行版本。新仓库从空白治理边界开始，避免把历史快照、临时备份、运行数据和业务源码混为主线。

## 受控来源

| 来源 | 角色 | 使用方式 |
| --- | --- | --- |
| openEuler 当前生产环境 | 运行行为与 active 服务的事实源 | 逐模块只读核验、来源 hash、受控导入 |
| 生产 MQTT/GaussDB 接入 | Topic、数据契约、规范传感数据链来源 | 导入前审查，不直接复制运行配置或数据 |
| Phase1 / Phase3 多设备控制 | 控制与安全逻辑来源 | 按设备、按服务独立导入和回放 |
| Web 服务 | 只读展示与交互来源 | 保持直控禁用语义 |
| Plant Agent / OpenClaw | 状态、推理、工具与受限交互来源 | 仅白名单代码和无密模板 |
| ESP32 / hardware | 设备执行边界来源 | 取得可追溯源码与构建信息后才导入 |
| 历史 GitHub 仓库 | 历史工程与同步对照来源 | 作为比较基线，不作为覆盖来源 |

## 这不是什么

- 不是旧仓库目录移动或重命名；
- 不是生产代码的批量复制；
- 不是自动部署仓库；
- 不是模型、数据库和运行时状态的备份仓库；
- 不是允许 Agent、Web 或实验代码直接获得泵控制权的接口。

## 维护原则

1. **来源可追溯**：每项导入记录来源路径、采集时间、SHA-256、导入提交与验证结果。
2. **生产与主线分离**：Git 提交不自动改变生产，生产热修复也不自动成为公开代码。
3. **工程与研究分离**：可部署服务不依赖 notebook、实验权重或外部模型；实验候选不能直接执行浇水。
4. **安全优先**：控制路径、人工例外、MQTT 合同和设备执行边界必须显式记录。
5. **隐私与密钥最小化**：运行记忆、会话、账号、生产数据、私有地址和凭据永不提交。
