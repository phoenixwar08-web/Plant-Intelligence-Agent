# 统一补水预算：本地Review

2026-11-17，Owner确认滚动24小时累计最多30秒。本变更未部署，未操作生产或水泵。

## 核算位置与含义

`MODEL_PROPOSAL_BUDGET_24H_SEC=30.0`沿用现有配置名，但最终预算适用于每一个Phase3正时长开泵调用。`ActuatorLayer._activate_pump`在MQTT ON之前持久化预留；普通脚本、AI、脚本回退、紧急、受控执行均不能通过切换模式跳过。无单独预算关闭开关。零秒观察和强制OFF不需要账本。

账本位于Phase3 `SYSTEM_STATE`同目录的`watering_budget.sqlite`；SQLite事务和FULL同步串行化检查、预留与提交。账本只写本设备控制目录，不写Gauss数据库或历史原始数据。

- 已完成命令：按OFF完成时间向前滚动86400秒统计，边界恰好24小时后到期。对于与窗口相交的命令保守计入整段秒数，不在午夜清零。
- 未完成命令：包括崩溃、ON回执不明、OFF失败，持续占用并阻止新ON，不因重启或经过24小时自动释放；须人工查明后另行审核修复，当前不提供自动清除接口。
- MQTT等待后同时确认`rc=0`与`is_published()=True`；仅本地接受但发布等待超时不算完成。这里确认的是发布流程，不是ESP32物理继电器或出水的独立回执。
- 原模型提案claim仍用于防重放；不与共享账本相加重复扣款。即使上游允许，共享账本仍可在最终ON之前拒绝。被拒绝的提案可能已claim，不自动重放。
- 超额、缺失/损坏账本、时钟倒退、未来记录及不合法数值均拒绝ON。不会自动删账、创建空账本或降低请求秒数以硬凑余额。
- 本账本记录请求执行的命令秒数；MQTT延迟、调度误差和物理流量并非独立测量。外部直接MQTT、ESP32本地按钮或独立人工工具不受此路径控制，部署前须关闭这些旁路或单独完成受控接入，不能宣称已实现全设备硬上限。

## 首次部署迁移：必须人工核实，守护进程不自动执行

1. 仅在获准统一发布时暂停全部开泵发布者，确认泵OFF、无在途命令；保存回滚证据。账本初始化与新代码启动之间不得发生漏记动作。
2. 汇总初始化时点之前完整24小时的所有来源命令，核实时间、设备、实际记录来源及不确定动作。不能把缺少记录当0；存在未查明动作时不要初始化空账本、不要启用。
3. 在离线迁移环境调用`PumpBudget(path).bootstrap(now, coverage_start, entries, evidence=reference)`。`now`与`coverage_start`为Unix秒，coverage_start必须不晚于now−86400；每个entry包含`source`、正数`seconds`、`completed_at`。reference应指向经核实的历史证据，不含密钥。空entries仅用于已核实完整窗口确实无补水的情形。
4. bootstrap拒绝覆盖现有文件。数据库缺失/损坏时保留现场、阻断ON，不得为恢复服务直接重建空账本。若历史无法核实，可以在全部来源停止浇水满24小时并核实无动作后再初始化；这不是建议主动让植物缺水，应由Owner评估并照护。
5. 使用当前Phase3唯一执行服务启动、验收。须保持账本路径、权限和备份连续，禁止运行另一份独立账本控制同一设备。

这里没有新增独立人工控制入口。人工若通过正式Phase3开泵路径即共用预算；仓库中未找到独立manual_water实现，不推测生产工具均已接入。
